# 05 · كيف تمرّر خادم Linux وأدوات سطر الأوامر عبر الخط

على Linux طريقان إلى الخط، فاختر حسب حاجتك. لتمرير الجهاز كله (سحب صور Docker، وتشغيل خدمات تحتاج إلى شبكة خارجية، والعمل دون إشراف) استخدم OpenVPN: ملف إعداد واحد تضعه في /etc/openvpn/client/ ويعمل مع الإقلاع. ولتمرير بضعة أوامر فقط (git وpip وnpm وcurl) استخدم بروكسي الويب: ضع عنوان البروكسي في متغير البيئة http_proxy، ولا تُمسّ بقية الحركة. وعلى Linux المكتبي يمكنك أيضًا الاستيراد في NetworkManager. يشرح هذا المقال الطرق الثلاث، مع طريقة كتابة ملف كلمة المرور وأوامر التحقق.

## الطريق الأول: الجهاز كله عبر الخط (OpenVPN)

1. ثبّت التطبيق: على Debian / Ubuntu ‏sudo apt install openvpn، وعلى Fedora ‏sudo dnf install openvpn، وعلى Arch ‏sudo pacman -S openvpn.
2. سجّل الدخول إلى موقعنا، وفي صفحة OpenVPN انقر على علم المنطقة لتنزيل ملف ‎.ovpn. الإعداد الذي يصل إلى Linux لا يحتوي على الحساب وكلمة المرور (لأن NetworkManager لا يقبل ملفات تتضمن بيانات الاعتماد)، فأنشئ ملف كلمة مرور منفصلًا: سطران، الأول بريدك في موقعنا والثاني كلمة مرورك، ثم chmod 600.
3. انسخ ملف ‎.ovpn إلى /etc/openvpn/client/<region>.conf، وأضف مسار ملف كلمة المرور بعد auth-user-pass في الملف.
4. sudo systemctl enable --now openvpn-client@<region>. وتحقق من الحالة بـ systemctl status openvpn-client@<region>، وتأكد أن curl -s https://ipinfo.io/country يعرض المنطقة التي اخترتها.
5. لتغيير المنطقة نزّل إعدادًا آخر وفعّل وحدة أخرى؛ وشغّل وحدة واحدة فقط في كل مرة.

## الطريق الثاني: أدوات سطر الأوامر وحدها عبر الخط (بروكسي الويب)

عنوان البروكسي المعروض في صفحة Proxy في موقعنا، مع حسابك وكلمة المرور، يمكن وضعه مباشرة في متغيرات البيئة: export https_proxy=https://username:password@proxy-address export http_proxy=$https_proxy. والرموز الخاصة في كلمة المرور يجب ترميزها بترميز URL. بعد ذلك تمر curl وwget وgit وpip وnpm كلها عبر الخط في هذه الطرفية، ولا تتأثر البرامج الأخرى.

خدمة Docker (daemon) لا تقرأ متغيرات بيئة الصدفة؛ فاكتبها في Environment=‎ داخل /etc/systemd/system/docker.service.d/proxy.conf وأعد تشغيل docker. ولـ apt اكتب Acquire::https::Proxy في /etc/apt/apt.conf.d/proxy.conf.

في هذا الطريق لا يوجد اتصال ينقطع أصلًا بحكم التصميم؛ ولا يحتاج إلى صلاحيات root ولا يغيّر المسارات. ويناسب خوادم الشركات والحالات التي تريد فيها تسريع السحب فقط؛ ولا يسري إلا على البرامج التي تحترم متغيرات البروكسي، ولا تُمسّ بقية الحركة.

## الطريق الثالث: NetworkManager على Linux المكتبي

1. ثبّت network-manager-openvpn-gnome (نقرة واحدة في صفحة OpenVPN على موقعنا تفتح مركز البرمجيات).
2. Settings ← Network ← VPN ← «+» ← Import from file (الإعدادات ← الشبكة ← VPN ← «+» ← الاستيراد من ملف)، واختر ملف ‎.ovpn، وأدخل بريدك وكلمة مرورك في موقعنا، ثم احفظ.
3. شغّل VPN وأوقفه من الشريط العلوي أو من منطقة الإشعارات. وللاتصال التلقائي مع الإقلاع ضع علامة على «Automatically connect to VPN» (الاتصال بـ VPN تلقائيًا) في إعدادات الاتصال السلكي أو اللاسلكي.

## التحقق وحل المشكلات

- افحص نقطة الخروج: البلد في curl -s https://ipinfo.io هو المنطقة التي اخترتها.
- افحص DNS: في resolvectl status يجب أن يكون DNS واجهة VPN هو الذي يرسله الخط؛ وإن تسرّب فأضف dhcp-option DNS إلى الإعداد أو استخدم سكربت update-systemd-resolved.
- AUTH_FAILED: ملف كلمة المرور خطأ أو انتهت صلاحية الحساب؛ وإن غيّرت كلمة المرور فحدّث ملف كلمة المرور.
- انتهاء مهلة مصافحة TLS: حركة UDP إلى الخادم لا تمر؛ غيّر المنطقة أو الشبكة. وعلى الخادم السحابي يجب أن تسمح مجموعة الأمان (Security group) بحركة UDP الخارجة.
- الخادم في الصين وتريد أن تتصل المصادر الصينية مباشرة: بعد اتصال OpenVPN تمر كل الحركة الخارجة عبر الخط. غيّر مصادر apt / pip / npm إلى مرايا صينية، أو استخدم الطريق الثاني بدلًا منه ليمر عبر الخط أوامر محددة فقط.

## أمور يجب معرفتها

- جهاز Linux الواحد يُحسب جهازًا واحدًا ويتقاسم حد الأجهزة المتصلة في آن واحد مع أجهزتك الأخرى («شخصي» جهازان، «عائلي» 4 أجهزة، «مؤسسات» 8 أجهزة)؛ وبروكسي الويب في الطريق الثاني يُحسب لكل اتصال ويدخل في الحد أيضًا.
- ملف الإعداد وملف كلمة المرور بمثابة حسابك؛ فلا تضعهما في مستودع git ولا داخل صورة (image).
- بعد تغيير كلمة المرور يتوقف الإعداد القديم عن العمل فورًا؛ وهذه آلية الإلغاء المقصودة. ويكفي تحديث ملف كلمة المرور.
- عند تشغيل الخط على خادم سحابي التزم بشروط استخدام مزوّد الخدمة السحابية؛ ولا يسجّل الخط إلا مدة الاتصال وإجمالي حجم البيانات.

## أسئلة شائعة

**لماذا لا يحتوي إعداد Linux على الحساب وكلمة المرور؟** حين يستورد NetworkManager إعدادًا لا يقبل ملفًا يتضمن بيانات الاعتماد ويُبلغ عن فشل الاستيراد، لذا فالنسخة المخصّصة لـ Linux تتركك تملؤهما بنفسك؛ وفي طريقة systemd اكتبهما في ملف كلمة المرور.

**هل يمكن أن يمر Docker وحده عبر الخط؟** نعم: اضبط متغيرات البروكسي لخدمة Docker وحدها (الطريق الثاني)؛ أو شغّل حاوية فيها OpenVPN ‏(gluetun) لتمر حاويات محددة عبر الخط.

**وماذا عن الشبكة «خاصة» (Tailscale) على Linux؟** السكربت الرسمي يثبّتها بسطر واحد، وtailscale up --login-server=<خادم التحكم في موقعنا> يسجّل الدخول. وتناسب الحالات التي تحتاج فيها إلى الوصول إلى هذا الجهاز من الخارج، أو تريد إعداده مرة ليبقى متصلًا دائمًا؛ أما لمجرد تسريع السحب فـ OpenVPN أو البروكسي أبسط.

**هل الأمر نفسه مع OpenWrt على الراوتر؟** على OpenWrt ثبّت luci-app-openvpn وارفع ملف ‎.ovpn، فتمر الشبكة المحلية كلها عبر الخط؛ والراوتر الذي يعمل بالبرنامج الثابت من موقعنا لا يحتاج إلى ذلك، يكفي تسجيل الدخول بحسابك.
